# Git Commit Guide

You need at least **4 meaningful commits**.

A strong development history might look like:

1. `Add defect report and project structure`
2. `Implement tank fill calculation`
3. `Add workbook verification tests`
4. `Reject invalid tank dimensions`
5. `Document units assumptions and limitations`

Avoid commit messages such as:

- `update`
- `stuff`
- `changes`
- `final`

Your commit history should show how the engineering work developed over time.
